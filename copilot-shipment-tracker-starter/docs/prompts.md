# 用 Spec Kit 新增本机跟进保存

用 VS Code 直接打开本项目。先看 [数据来源与表关系](data-source.md) 和 [新增功能效果稿](../mockup/index.html)，再逐条发送下面的消息，每步审阅后继续。

现有应用已经能读取和查看异常。本轮新增“保存到本机并重新读取确认”，课堂时间沿用原安排。

## 1 生成新增功能规格

```text
/speckit-specify 参考 docs/data-source.md 和 mockup/index.html，在现有运输异常队列上新增本机跟进保存。用户选择异常后更新状态、填写备注并保存，系统重新读取同一异常，确认状态和备注后显示成功；刷新及使用相同数据库重启后仍保留。按 exception_id 独立保存，不改 Databricks 源记录或同运输单的其他异常。状态流转、备注和过期提交规则按数据说明确认，明确保存失败与已提交但未确认的反馈。已有读取、筛选、分页和详情保持原功能。
```

课堂新增条件直接补在这条消息后面。

## 2 澄清边界

```text
/speckit-clarify 聚焦状态能否跳过、同状态备注、备注长度、原状态过期、保存位置和重读确认失败；已明确的规则沿用。
```

## 3 生成增量方案

```text
/speckit-plan 沿用已有 Python、uv、只读 MCP 和原生前端，复用校验、SQLite 连接与 overlay。后端补 FollowUpStore.save，前端补 submit 的 POST 后 GET 确认及必要测试，不重写现有读取和队列。
```

## 4 拆任务并检查一致性

```text
/speckit-tasks 按后端保存、前端确认和最终验收拆分本次新增功能，包含非法输入、过期提交、独立异常和同库重启恢复的必要测试。
```

```text
/speckit-analyze
```

## 5 实现后端保存

```text
/speckit-implement 只执行后端保存与必要测试任务，复用已有规则和事务连接，按 exception_id 写本机 SQLite，核对原状态并拒绝非法更新，失败不留下部分写入。
```

## 6 实现前端确认

```text
/speckit-implement 只执行前端提交与必要收尾任务，参考 mockup，POST 后 GET 同一异常核对状态和备注，确认后更新页面；区分失败与尚未确认，保存期间防止重复提交。
```

## 7 验收新增功能

```text
/speckit-converge 对照本次 spec、tasks 和 README，核对保存、重读、刷新、同库重启恢复、非法输入、过期状态及同单其他异常保持独立。确认已有列表和详情没有回归；分别报告离线、真实 MCP 与页面验收，未验证项据实说明。
```

生成规格与检查通过不等于保存功能已实现，按本次实际代码与执行结果验收。

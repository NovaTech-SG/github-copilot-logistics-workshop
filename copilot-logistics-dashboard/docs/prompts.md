# Spec Kit 课堂提示词

在Copilot Agent聊天框逐条发送下列内容。确认斜杠菜单存在对应技能；这些不是终端命令。
当前活动目录：`specs/001-carrier-dashboard`。已有规格、计划和任务是课前准备的可恢复检查点。

## 1. 业务需求生成规格（讲师演示）
```text
/speckit-specify 物流同事需要按承运商查看运输总量、有效分母、准时率和延误量，支持筛选和清除，所有组件范围一致。课堂先做P1，趋势与分页留作P2。 SPECIFY_FEATURE_DIRECTORY=specs/001-carrier-dashboard。在既有项目和确认的教学规则内更新活动规格，先看AGENTS.md、constitution和现有spec，保留验收边界，不修改应用代码。
```

## 2. 澄清业务边界（讲师演示或学员回答）
```text
/speckit-clarify 聚焦准时率分母、时间相等、零分母和P1范围。已有答案先引用活动规格，不重复询问已确认的问题；若已完整，说明无需新增澄清。只更新当前活动规格。
```
如果没有新歧义，clarify可以结束且没有提问。课堂可用spec中的既有澄清记录解释原因，不能虚构自动弹出的问答。

## 3. 技术计划与任务（课前准备，课堂看结果）
```text
/speckit-plan 沿用Python3.12、uv、原生前端、已有只读MCP和当前接口。P1实现指标、承运商筛选和对比图，P2另行安排。 不改源表，不新增依赖，不读取相邻完成版。技术选择写入当前活动plan，不改业务口径。
```
```text
/speckit-tasks 按当前活动spec与plan生成有ID和依赖顺序的任务。保留P1课堂范围与明确测试任务，已经预置的基础结构先核对后再勾选，不把预置文档当运行证据。
```

## 4. 实现指定范围（学员跟练）
```text
/speckit-implement 只执行当前功能Phase 1至Phase 3的P1任务和该范围必要收尾，不执行P2。 先给出拟改文件，再小步实现。保持运行时MCP真实数据、源只读与凭据边界。只在当前项目内工作，不读取相邻完成版。按实际执行更新任务状态，报告离线和实时验证，尚未执行的项目保持未完成。不要提交、推送或部署。
```

## 5. 规格一致性与缺口检查
```text
/speckit-analyze 检查当前spec、plan和tasks是否一致，重点核对业务口径、数据来源、课堂范围及验收覆盖。只读报告，不修改应用。
```
```text
/speckit-converge 只核对本次P1实现，P2是已知扩展，不自动补做。 对照实际代码、测试和页面验证找缺口；不能仅因任务勾选就宣称完成。把真实缺口补为任务，实时环境未验证时明确说明，不自动提交或部署。
```

# Dashboard 演示流程

本目录是完成版，学员起始项目为同级 `copilot-logistics-dashboard-starter`。培训前完成环境与权限检查；两个项目分别打开，完成版8766、学员项目8767。

主流程：先展示完成效果约1分钟，再切到学员项目，按其中 `docs/tasks.md` 和 `docs/prompts.md` 用约15分钟完成指标、筛选和对比图；趋势与分页留作扩展。学员项目已预置MCP连接，业务查询和页面需要现场实现。不要让起始项目的Agent读取完成版。

下文保留“基于完成版增加一个指标”的备用演示，适合时间较短或学员环境进度不同的场次。它与起始项目开发二选一，不在15分钟内连续安排两套。

## 课前检查

1. 打开本项目，阅读 `AGENTS.md` 和 `docs/spec.md`，用 uv 同步依赖。
2. 确认 Copilot 已登录、Agent 可用、`databricksTraining` 已发现只读工具。
3. 运行 `uv run --locked python app.py --vscode-config --check`，核对500/380/304/80%。
4. 启动网页，确认筛选、分页与错误展示可用。确认投屏中无 Token。

## 1. 用 MCP 确认数据（约2分钟）

在 Copilot Agent 中输入：

> 使用 databricksTraining 的只读 SQL 工具，查询 dev_databricks.default.shipments 和 carriers 的表结构，以及各自记录数。只执行读取操作，等待真实结果后再回答；不要根据文档猜测结果。

预期500条运输单、4个承运商。说明 Copilot 获取上下文与应用运行时查询的区别。

## 2. 从规则到修改计划（约3分钟）

> 阅读 AGENTS.md 和 docs/spec.md，说明准时率的分子、分母和零分母规则。结合当前实现，计划在指标区增加“数据完整性”提示：显示已送达但缺少计划或实际到达时间的单量，并随承运商筛选变化。先给出改动文件与验收条件，再实现。

整体缺失时间记录为20条，CAR002为6条。后端已有 `missing_timestamp_count`，可让 Agent 复用现有返回字段，避免重复查询。讲师检查计划是否扩大范围。

## 3. 实现并跟练（约6分钟）

> 按计划实现。复用 MCP 已返回的 missing_timestamp_count，保持运行时读取 MCP。沿用页面样式，不新增依赖。完成后运行现有测试和 JavaScript 语法检查，列出改动摘要。

学员跟练：完成提示，打开本地页面，切换 CAR002，再清除筛选。检查20→6→20。请学员解释为什么该缺失量没有纳入准时率分母。

## 4. 验收与 diff（约4分钟）

> 对照 docs/spec.md 检查本次改动，确认筛选后指标、图表和明细一致，没有固定500、80%等业务结果。给出测试结果和仍需人工验证的项目。不要提交凭据。

在 VS Code 检查改动，验证500/134单筛选及第2页明细。PR/CI环节使用这个小改动；创建 PR 前检查仓库地址、分支和提交范围。CI只执行离线测试和语法检查，不访问课堂凭据、不部署服务器。

## 连接异常时

先检查网络、MCP工具状态、Token权限和表权限。恢复后重新查询。不要改成本地 CSV 或硬编码结果；可以使用已准备的演示截图讲解，并明确这是预先录制的结果。

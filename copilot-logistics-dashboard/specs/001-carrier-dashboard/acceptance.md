# Dashboard 需求与验收

## 目的与边界

讲师用 Copilot 展示从业务规则、项目指令、查询到本地应用的开发过程。当前仓库为可运行基线，用于现场增量修改与验收。物流异常处理应用另行准备，不纳入本次代码。

数据来自 Databricks MCP 查询 `dev_databricks.default.shipments` 和 `carriers`。模拟数据明确标注。运行时必须真实调用 MCP，无 CSV 或固定业务数据兜底。页面包含承运商筛选、运输总量、有效分母、准时率、延误量、承运商对比、每日单量、20 条一页的明细。

## 规则

有效分母仅统计 DELIVERED 且计划/实际到达时间均非空的运输单。实际到达时间 <= 计划到达时间算准时。延误=有效分母−准时，排除=总量−有效分母。整体准时率使用总准时量/总有效分母。零分母为 NULL，页面显示 N/A。按 shipment_date 生成每日趋势，自然日缺失补零。时间统一显示 Asia/Shanghai。指标不关联一单多异常的 exceptions 表。

## 验收条件

1. 无筛选时总量500、有效分母380、准时304、延误76、排除120、准时率80%。
2. CAR002 时总量134、有效分母104、准时77、延误27、准时率74.04%；图表和明细均属于 CAR002。
3. 明细每页20条，第1、2页不重复；最后一页正确显示剩余条数。清除筛选回到第1页及全部范围。
4. 空范围无明细、无趋势，零分母显示N/A；有运输单但无有效分母时同样显示N/A。
5. MCP 查询失败或结果被截断时显示错误，不展示旧结果或固定数值。
6. 浏览器不接收Token；源码与提交内容不含实际凭据。应用仅监听本机。
7. 页面展示数据快照与查询完成时间；当前数据快照为2026-11-05 12:00（上海）。
8. 桌面及390px窄屏可操作，表格可在容器内横向滚动，页面整体不横向溢出。

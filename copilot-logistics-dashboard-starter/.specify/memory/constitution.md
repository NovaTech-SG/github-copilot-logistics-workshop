# Dashboard 课堂项目原则

## 先形成规格再实现

课堂从可编辑的需求素材与静态效果稿开始。初始 specs 为空。通过 specify 形成业务规格，经人工核对后再 plan、tasks、implement；存在歧义时先 clarify。每一步分别调用，按实际生成的功能目录与任务推进。

## 源数据只读

业务数据由现有 Databricks MCP 连接获取，只调用 execute_sql_read_only 和 poll_sql_result，不写源表。mockup 的固定样例只说明视觉目标，CSV、聊天结果和硬编码答案都不能作为运行时数据或失败兜底。

## 独立项目与凭据边界

只在当前项目工作，不读取相邻完成版、内部备份或 Git 历史中的解答。Python 3.12、独立 uv 环境和原生前端；复用现有连接与 HTTP 骨架，避免不必要的新依赖。Token 只在后端，不输出、不提交、不进入页面。

## 先完成本次范围

P1 包括核心指标、承运商筛选、清除和准时率对比，以及加载、错误、空结果和重试。趋势、日期补零、明细分页为 P2，不能因为效果稿中展示就自动实现。业务条件和准时率口径由需求进入 spec 后确认。

## 用执行证据验收

结构检查允许没有规格、仅有 spec、已有 plan 和已有 tasks 的阶段；通过不表示业务完成。测试覆盖本次业务规则，离线检查、实时 MCP、页面操作与远程 CI 分别记录。每步先审阅产物再继续，不自动提交、推送或部署。

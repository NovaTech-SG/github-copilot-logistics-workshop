# 物流 Dashboard · 业务规格

## 目标

从培训模拟运输数据中查看运输表现，比较承运商准时率，并通过筛选定位需要跟进的承运商。

应用仅在本地运行。浏览器调用本地Python API，后端通过Databricks MCP读取实际结果。开发时Copilot可调用同一MCP查看表结构和核对结果。

## 数据

默认使用 `dev_databricks.default.shipments` 与 `dev_databricks.default.carriers`。字段结构以实际MCP查询结果为准。

主要运输字段：shipment_id、carrier_id、shipment_date、origin_city、destination_city、planned_arrival、actual_arrival、status、snapshot_at。承运商字段：carrier_id、carrier_name。

状态包括DELIVERED、IN_TRANSIT、CANCELLED。数据是培训模拟数据，页面需明确标识。

## 业务规则

1. 有效分母：DELIVERED，且计划到达时间和实际到达时间均非空。
2. 准时：实际到达时间不晚于计划到达时间，相等算准时。
3. 延误量=有效分母−准时量；排除量=总量−有效分母。
4. 整体准时率=总准时量/总有效分母，不取承运商百分比的算术平均。
5. 分母为零，返回NULL并显示N/A；不能显示0%或报除零错误。
6. 承运商筛选后，所有已实现组件必须使用同一范围。
7. 不关联一单多异常的exceptions表，避免重复计数。
8. 趋势按shipment_date，缺失自然日补零；时间显示Asia/Shanghai。数据快照与查询时间分别标注。

## 基础跟练范围

- 总量、有效分母、准时率、延误量四个指标。
- 承运商筛选和清除筛选。
- 承运商准时率对比图，附准时量和有效分母。
- 加载、空数据、连接失败与重试状态；失败隐藏旧结果。
- 后端复用已有连接模块，仅调用只读SQL工具，查询未完成时轮询。

## 扩展练习范围

- 每日运输单量趋势，缺失自然日补零。
- 20条一页的运输明细，SQL分页，筛选改变时回到第1页。
- 显示快照、查询时间，以及“已送达但缺少到达时间”的记录量。
- 对本次行为补测试，检查diff，准备PR与CI。仅CI，无CD或服务器部署。

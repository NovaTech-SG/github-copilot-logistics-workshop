# 用 Spec Kit 完成物流 Dashboard

用 VS Code 直接打开本项目。先看 [数据来源与表关系](data-source.md) 和 [静态效果稿](../mockup/index.html)，再将下面消息逐条发到 Copilot Agent 聊天。每步审阅结果后继续，项目规则与产物格式由已配置的指令和 Spec Kit 技能处理。

先完成 P1，再按课堂安排补齐 P2，即可逐步形成完整看板。课堂时间沿用原安排。

## 1 生成业务规格

```text
/speckit-specify 参考 docs/data-source.md 的数据来源、表关系和统计口径，以及 mockup/index.html 的目标效果，为物流运营同事创建运输表现看板。运行数据来自 Databricks 只读 MCP。P1 展示运输单量、有效计算单量、准时率和延误单量，支持承运商筛选、清除、重新查询与准时率对比，并处理加载、空范围、N/A 和失败重试。P2 增加按 shipment_date 的每日单量趋势并补齐缺失自然日、每页 20 条的运输明细、筛选后回到第 1 页，以及快照与查询完成时间的分别展示，时间显示为 Asia/Shanghai。P1、P2 分开定义验收条件。
```

课堂新增的业务条件可直接补在这条消息后面。

## 2 确认有歧义的业务边界

```text
/speckit-clarify 聚焦准时率分母、时间相等、零分母、筛选一致性、日期范围和查询失败行为；已明确的规则沿用。
```

## 3 生成技术方案

```text
/speckit-plan 沿用本项目 Python、uv、只读 MCP、HTTP 服务和原生前端骨架，参考 services/mcp_sql.py 的现有接口。P1 分后端、前端两轮，P2 单列；明细在 SQL 侧分页，保持结果完整性检查。
```

## 4 拆任务并检查一致性

```text
/speckit-tasks 按 P1 后端、P1 前端、P2 扩展和最终验收拆任务，包含各轮必要测试，明确依赖顺序。
```

```text
/speckit-analyze
```

## 5 实现 P1 后端

```text
/speckit-implement 只执行 P1 的后端查询、参数校验、指标和必要测试任务，完成后报告结果。
```

## 6 实现 P1 前端

```text
/speckit-implement 只执行 P1 前端任务，参考 mockup 完成四指标、承运商筛选与清除、重新查询和对比图，以及加载、空结果和失败重试；所有业务数值来自本地 API。
```

完成后按 README 验收 P1。P2 在后续安排时再继续。

## 7 补齐完整看板的 P2

```text
/speckit-implement 执行 P2：每日单量趋势与缺失自然日补零、20 条一页的运输明细、筛选后回第 1 页、快照与查询时间标注及相应测试。指标、图表和明细保持同一范围，布局参考 mockup。
```

## 8 验收完整结果

```text
/speckit-converge 核对全部 P1、P2 的实现与验收证据，检查指标、筛选、趋势合计、分页边界和错误反馈。按 README 运行离线检查，再核对实际 MCP 与桌面、窄屏页面。分别报告已验证、失败和未验证项。
```

完成实现需要实际运行上述步骤、核对生成内容和执行验收；提示词本身不代表功能或实时连接已通过。
